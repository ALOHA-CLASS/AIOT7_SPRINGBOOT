# 📋 Spring Boot & Slf4j 로깅 처리 가이드라인

본 가이드라인은 프로젝트 내 일관되고 효율적인 로그 관리를 위해 **Slf4j(Lombok)** 및 **Logback** 사용 표준을 정의합니다.

---

## 1. 기본 원칙

1. **`System.out.println()` / `System.err.println()` 사용 절대 금지**
   - 표준 출력 스트림은 I/O 병목을 유발하며, 로그 파일 저장 및 레벨 관리가 불가능합니다.
2. **Lombok `@Slf4j` 어노테이션 사용**
   - 별도의 `LoggerFactory` 정의 없이 클래스 상단에 `@Slf4j`를 선언하여 사용합니다.
3. **치환 문자열 (`{}`) 활용**
   - 문자열 더하기(`+`) 연산은 로그 출력 여부와 상관없이 객체 생성 비용이 발생하므로 **반드시 `{}` 치환자**를 사용합니다.

```java
// ❌ 잘못된 예시 (문자열 연산 + System.out)
System.out.println("User id : " + id + ", name : " + name);
log.debug("User id : " + id + ", name : " + name); 

// O 올바른 예시
log.debug("User id : {}, name : {}", id, name);
```

## 2. 로그 레벨(Log Level) 정의 및 사용 기준

| 로그 레벨     | 설명                            | 주요 사용 위치 및 용도                                  |
| --------- | ----------------------------- | ---------------------------------------------- |
| **TRACE** | 가장 상세한 추적 정보                  | 매우 세밀한 디버깅, 로직 내 상세 변수값·흐름 추적                  |
| **DEBUG** | 개발 및 디버깅 목적의 상세 정보            | 개발 환경에서 비즈니스 로직, SQL 쿼리, 요청·응답 데이터 확인          |
| **INFO**  | 애플리케이션의 주요 비즈니스 상태 및 이벤트      | 서버 시작·종료, 주요 API 요청 완료, 회원가입·결제 성공 등           |
| **WARN**  | 당장 시스템 장애는 아니지만 주의가 필요한 상태    | 비즈니스 유효성 검증 실패, Deprecated API 호출, 시스템 리소스 경고  |
| **ERROR** | 시스템 동작 장애 또는 예외(Exception) 발생 | `catch` 블록, DB 연결 실패, 외부 API 연동 실패, 시스템 치명적 오류 |
